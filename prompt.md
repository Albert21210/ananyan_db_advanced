# Роль
Ты опытный разработчик PostgreSQL / PL/pgSQL. Нужно выполнить учебное задание по базе данных.

# Задание
Разработать расчёт приближенного метеобюллетеня («Метеосредний») для двух типов оборудования: ДМК (десантный метео комплект) и ВР (ветровое ружьё).

# Вложения
1. Текст задания (что нужно сделать).
2. Техническое задание (`TechnicalTask.md`).
3. Описания алгоритмов (`AlgoritmDmk.md`, `AlgoritmBp.md`).
4. Учебный скрипт `20261102.sql` (основа решения).
5. Справочные данные: Таблица 2, Таблица 3 (текст и картинки).

# Что сделать
1. Взять учебный скрипт за основу и **не менять в нём ни одной строки**. Все изменения добавить новыми блоками (diff), результат должен выглядеть как «учебный скрипт + добавления».
2. Все изменения оформить **вложенными блоками `begin ... end;` внутри одного `DO`**, а не отдельными `DO`.
3. Сверить справочники с таблицами из вложений: исправить ошибки в данных (через `UPDATE`), добавить недостающие данные (высоты 1600–4000 м). Каждое исправление отметить комментарием: что было, что стало, почему.
4. Добавить отдельную таблицу для хранения заголовков таблиц и изменить структуру справочника типов так, чтобы он ссылался на неё (внешний ключ). Добавить недостающие ключи и ограничения.
5. Создать составной тип «входящие параметры» (высота, температура, давление, направление ветра, скорость ветра, дальность сноса).
6. Написать хранимую процедуру расчёта: вход — тип «входящие параметры» и тип оборудования, выход — H, TT, HH, CC по каждой типовой высоте. Алгоритм строго по описаниям из вложений. Добавить проверку входных данных по диапазонам из ТЗ.
7. Добавить `comment on` ко всем новым таблицам, столбцам, типам, функциям, процедурам.
8. Написать отдельный тестовый скрипт: расчёт для типовых данных из ТЗ (ДМК и ВР), проверки через `assert` и запрос для скриншота.

# Требования
- Простой читаемый синтаксис: без глубоко вложенных подзапросов и лишних сложных конструкций (`CASE` внутри `CASE` и т. п.). Вложенные блоки `begin ... end;` внутри одного `DO` при этом обязательны (см. пункт 2).
- Код разделить пустыми строками на логические блоки.
- Если в ТЗ или данных чего-то не хватает или есть противоречие, **не выдумывай**: перечисли допущения отдельным списком в конце.
- Результат проверь: пересчитай ожидаемые значения тестов независимо от кода (например, скриптом) и убедись, что они совпадают.

# Формат ответа
1. Файлы: `main.sql` (учебный скрипт + изменения), `test.sql`.
2. Краткий список того, что исправлено в данных и что добавлено.
3. Список допущений и того, что нужно проверить вручную.
